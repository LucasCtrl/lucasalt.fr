Keyboard enthousiast for five years now and happy owner of a BambuLab P1S since spring 2025 I wanted to print a keyboard to combine both of my hobbies.

# Design

## Layout

Printing a full size keyboard in one piece is outside the capabilities of the 3D printer as the maximum printing dimensions are 256x256x256mm but keyboard sizes are not limited to full size keyboard like we know from Corsair, Logitech, ...

Smaller keyboards exists and I enjoy really small keyboards called 40%. They "lack" the numpad, arrow cluster, F row, numrow, ...

It basically a keyboard with only the alphas (letters).

![Keyboard Layout Editor](/img/EK_10/keyboard-anatomy.jpg)

You will say: Great, but can you write with this ? Short anwser, yes.

With a small keyboard, you will only have the possibility to write lowercase letter. So to improve or add new characters without adding new keys, we will use a function called layers.

But what are layers you will ask. Think about the `Shift` key. When you press on the letter `a`, you have a lowercase `a`. By pressing on `Shift + a`, you will go to a layer for uppercase letters and an uppercase `A` will appear on your screen. With a 40% keyboard, you will not only have 1 or 2 layers but 3 or 4 with specific purposes (layer 1 for uppercase letters, layer 2 for symbols, layer 3 for numbers, ...).


Now I know, that I want a 40% keyboard, but which layout. Something identically to a [Minivan](https://40s.wiki/boards/minivan), a [Le Chiffre](https://40s.wiki/boards/le_chiffre), a [QAZ](https://40s.wiki/boards/qaz), ... ? I already own some of them or something apparenting to them, but something that I didn't tried yet is something like a [Planck](https://40s.wiki/boards/planck). An ortholinear keyboard which is 12u[^ft-note1] in length and 4u[^ft-note1] in height.

To simplify the design a make the keyboard even more compact, I'll trim down 2 columns and remove some unwanted keys at the bottom left and bottom right.

Now that I know a bit better where I will go with this, it's time to start sketch and visualize this keyboard on a computer. Some really great tools online exists and make our life easier.

## Design

### 1. KLE

After the keyboard layout defined, I always start with [KLE (Keyboard Layout Editor)](https://www.keyboard-layout-editor.com/). KLE is one of the most popular tool for keyboard enthousiast. It allow us to represent the keyboard from the top with all the keys, their specific size, position as well as the symbols defined under each keys. It's also the backbone of many project related to the keyboard community like the software on each keyboard, some automatic keyboard generators, ...

![Keyboard Layout Editor](/img/EK_10/kle.png)

Now I have my keyboard represented, I'm gonna grab the JSON data generated by KLE to use it "everywhere", ai03 plate generator for the automatic generation of the plate, QMK for the firmware of the keyboard, and for GitHub to populate the documentation about this project.

### 2. ai03 plate generator

After the JSON data grabbed from KLE, on [ai03 plate generator](https://kbplate.ai03.com/), I will be able to automatically generate the plate for my future keyboard. The tool is easy to use, fast and customizable. For example, I always disable the fillet because I like to defined them on the 3D model, I also like to customize my stabilizer orientation with the flags `_rs`. I generally do this to orient the wire of my stabilizer in the keyboard and not having it at the edge of the plate.

```json
[{a:7},"","","","","","","","","",""],
["","","","","","","","","",""],
["","","","","","","","","",""],
[{x:2},"","",{w:2,_rs:180},"","",""]
```

![ai03 plate generator](/img/EK_10/ai03_plate_generator.png)

Then, I can simply download the SVG or DXF file. He can be directly sent to a manufacturer to cut the plate to your needs or import them in a CAD software to edit the plate shape and design the keyboard around.

### 3. OnShape

Finally, the part where I'm like a fish in the water, one of my favorite part : CAD[^ft-note2]. I will now define the global shape of the keyboard. Until now, the only defined thing was the placement of the keys on my future keyboard. For this part of the process, many tools are available, free ones ([FreeCAD](https://www.freecad.org/), [OpenSCAD](https://openscad.org/), ...), freemium ones ([Fusion 360](https://www.autodesk.com/products/fusion-360/), [OnShape](https://www.onshape.com/), ...) and professional ones ([SolidWorks](https://www.solidworks.com/), [Creo](https://www.ptc.com/en/products/creo), ...). As a CAD[^ft-note2] and CAM[^ft-note3] trainer, I work with professional software every day but I don't want to spend a lot of money in the keyboard hobby especially for a CAD software. In that case, I prefere to look at free or freemium alternatives. Over the years, I tend to stick with OnShape who is more or less identical to Creo philosophy.

The first thing I like to do, even before sketching the case, is to define variables. Those variables will be very handy during the design process. The main purpose of the variables is to replace a dimension by a name, this name is then linked to a variable. If you use this variable across multiple drawings, features or files, by changing the variable value, the dimension will be changed everywhere. You can compare this to a formula in Excel, you have the possibility to use a cell value in a formula to calculate something. If a value change, you don't need to change the formula itself, just the value in the cell which was refered.

![OnShape tree view](/img/EK_10/variable_list.png)

After that, I tend to create a file per part, and regroup everything into sub-assemblies and assemblies. It can be complicated at first, because you need to maintain multiple files for the whole design but it approach the reality, you assemble (assembly file) multiple parts (part file) together.

![OnShape tree view](/img/EK_10/onshape_tree.png)

![Compact view](/img/EK_10/EK_10_compact.png)

![Exploded view](/img/EK_10/EK_10_exploded.png)

Once convinced by the result of the project, I exported all the parts as `.3mf` files to be able to import them in Bambu Studio to 3D print them.

## 3D Printing

With a printer from BambuLab, the setup process is pretty straight foward. I imported each component on their own plate and defined some parameters that I really wanted to change. But if you don't really care about the specific setting, you just have to import the file and press print.

By default, a slicer, the app that convert the 3D model to something printable, create an empty model. If you print the part, you will only have an empty shell and the part will not be very solid. To avoid this, parts are generally printed with a 10-20% infill to create a "scaffold" and reenforce the structure of the part. The benefit of printing a part with a low percentage of infill is that the printer will use less material and will be quicker to print the part, the downside is that the print will sound hollow. In keyboard design, we tent to avoid hollow sound, that why, the keyboard will be printed with a 100% infill at cost of material and printing time.

To print the part, the printer will melt plastic and deposit it on a plate via an extruder (tool head). To reach the desired part height, the tool head will deposit melted plastic on top of already extruded plastic, layer by layer. With the tool head installed on my printer, I can BambuLab suggest me to print layer between 0.12 and 0.28mm. If I print with a 0.12mm layer height, the print time will be longer than a 0.28mm. However, I will be able to print the part with a better resolution. In my case, my parts are not very detailed so I go with a 0.28mm layer height. With this choice, I managed to reduce the time by more than 50% !

```
Case height: 20 mm
Time per layer: around 3 min

With a 0.12mm layer height:
20 / 0.12 = 166.667 lets round it to 167 layers
167 * 3 = 501 min converted in hours, around 8h20

With a 0.28mm layer height
20 / 0.28 = 71.428 lets round it to 72 layers
72 * 3 = 216 min converted in hours, around 3h40
```

Another downside of 3D printing is called the seam. By default, when the printer finished a layer, he will start the next one on top of the starting position of the previous layer. On one or two layer, you dont really see it. For taller part, it create an effect like the seam of you shirt. To avoid this, the slicer try to automatically hide this at a corner of the parts. But in some cases, when the part is round or have rounded corner, you can't really hide the seam. To solve this, the seam position can be randomized on each layer and "only" create a teardrop effect where the printer started to print.

The last parameter I setup is a feature called `fuzzy skin`. The printer will deliberatly start to "vibrate" when he will print the outside of the part. It's allow us to hide deffect like the teardrop mentionned above. 

## Problems encountered

### Fuzzy skin in slicer

Even with "Outside only" select, as the part is opened at the USB-C cutout, fuzzy skin is generated inside the part

To avoid this, creation of a small wall to "trick" the slicer and create an outside wall.

Will need post-processing but can be easily done with an exacto knife and a lighter to melt back sharp edges

### Holes to small

M2 screws used

Drawn Ø2 holes but printer has a big tolerance. In some cases 2mm can be 1.9 even 1.8mm

I needed to drill the holes larger with a 2mm drill bit

I change the CAD model to avoid this issue if I need to reprint the part in the future 2mm -> 2.2mm
